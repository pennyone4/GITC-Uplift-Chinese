# GITC Uplift

GITC Uplift 是一款专为虚拟摄影打造的 DLSS 5 模组，通过 ReShade 使用 NVIDIA DLSS 神经渲染（DLSS-NR），并针对灵活性、易用性、稳定性和跨 API 兼容性进行了优化。支持 DirectX 9、10、11、12、Vulkan 和 OpenGL，也支持 32 位与 64 位游戏。安装后启用即可自动完成其余工作；关闭 NR 后，Uplift 会释放其占用的显存。

GITC Uplift 与 NVIDIA、ReShade 均无隶属关系。

## 所需组件

- NVIDIA GeForce RTX 显卡及较新的驱动程序。
- [ReShade](https://reshade.me)，并且必须支持完整的插件功能（Addon 版本）。请使用最新版；Vulkan 和 OpenGL 游戏需要 6.8 或更高版本。
- NVIDIA DLSS-NR 运行时 `nvngx_dlssnr.dll`，需要由你自行提供。310.8 仍是较旧 RTX 显卡上经过测试的版本；310.9.16 提供下文介绍的实验性控制项，并且只包含 50 系列显卡的 GPU 内核。Uplift 不包含任何 NVIDIA 文件，请选择适用于你显卡的版本。

## 其他 DLSS 5 插件

- **请使用 GITC Uplift 替代其他 DLSS-NR 插件**，例如 RenoDX 的 DLSS 和 DLSS 5 插件（`renodx-dlss*.addon64`）。请将它们从 ReShade 插件目录中移除；如果其他插件仍在加载，Uplift 将无法工作。

## 开始之前

- **仅限单人游戏。** Uplift 会挂接到游戏进程，反作弊系统可能会因此产生问题。请勿在联网游戏中使用。
- **杀毒软件警告：** 部分杀毒软件会将 ReShade 插件误报为威胁。每个发行版都会在 `SHA256SUMS.txt` 中列出文件的 SHA-256 校验值；你也可以自行从源码构建 Uplift（见“从源码构建”）。

## 安装

安装步骤很简单：
1) 从 [GitHub Releases](https://github.com/ghostinthecamera/GITC-Uplift/releases) 下载最新发行版。
2) 将发行版 `Addons` 文件夹中的所有内容（文件和 `GITC-Uplift` 文件夹）复制到 ReShade 插件目录。
3) 将 `nvngx_dlssnr.dll` 复制到 `GITC-Uplift` 文件夹中。
4) 将发行版 `Shaders` 文件夹中的文件复制到 ReShade 的 `Shaders` 文件夹。

安装完成！

- 从旧版 Uplift 升级？请先删除旧版的 `uplift.addon64`、`uplift.addon32` 和 `uplift-helper64.exe`，避免同时加载两个版本。还要用新版 `Uplift.fx` 覆盖旧文件。
- 除非游戏的 `ReShade.ini` 中通过 `AddonPath` 指定了其他位置，否则 ReShade 插件目录就是游戏目录。

## 使用方法

1) 启动游戏并按 Home 键打开 ReShade。
2) 切换到 **GITC Uplift** 选项卡，勾选 **启用**。

完成。选项卡顶部的状态卡会实时显示 NR 的运行状态：运行时为绿色；未运行时会说明原因和处理方法。

所有设置的图文说明请见[使用指南](https://github.com/ghostinthecamera/GITC-Uplift/wiki/Guide)。

**设置**区域包含以下选项：

- **NR 运行阶段：** **后处理（Present）**适用于所有游戏，处理最终画面。**DLSS后（After DLSS）**（仅限使用 DLSS 的游戏）会在游戏帧内、HUD 绘制前运行。**DLSS前（Before upscaling）**为实验性选项。
- **运动矢量：** 自动模式会代为选择。其他选项为 DLSS（游戏自带）、LaunchPad（iMMERSE LaunchPad 提供）、Lumenite（LumeniteFX 的 Kernel）和关闭。
- **原生蒙版混合模式：** 选择 NR 原生蒙版的组合方式，默认值为 1。
- **网络预设：** NR 310.9.16 支持 A：Legacy 或 B：Small FP8。
- **分辨率：** 全分辨率画质最好；较低的分辨率运行更快、显存占用更少。

**NR 运行阶段**和**分辨率**相互独立。DLSS后阶段会读取游戏升频后的输出画面。**全分辨率**会在该输出分辨率下运行 NR；**质量**、**均衡**和**性能**会先处理较小的图像副本，再将结果应用到完整的输出画面。

当前游戏不支持的选项会变灰；将鼠标悬停在选项上即可查看原因。设置会被保存，并会在条件允许时自动恢复生效。

在大多数游戏中，如果你在游戏内关闭 DLSS，NR 会自动切换到后处理；重新开启 DLSS 后也会自动切回。

下方的**外观**区域可用于调整画面效果。关闭 NR 后，Uplift 会在数秒后释放其显存。

使用 **NR 310.9.16** 时，**设置 → 网络预设**可选择 **Legacy** 或 **Small FP8**；**Runtime default** 会在该版本中选择 Small FP8。Uplift 默认仍使用 Legacy。切换网络会重新创建 NR 并重置其历史记录。**设置 → 原生蒙版混合模式**提供 0–3 的实验性模式，与 Uplift 自带的蒙版相互独立。NR 310.8 始终使用旧版网络，并忽略蒙版混合模式。Uplift 识别到 310.8 运行时后，会禁用这两个控制项并说明原因；网络选项会显示 Legacy。已保存的选择会为较新运行时保留。更改 Runtime path 会在下次启动游戏时生效。

预设 **A（1）**为 Legacy，**B（2）**为 Small FP8。提供的 DLL 不包含 C–G 预设所需的权重。**外观 → 风格**可选择独立的 A/B/C 处理风格（0/1/2），后续各层也可以单独设置风格。

**详细信息**会逐个报告已创建且被请求的处理层：网络名称取自 NVIDIA 成功创建功能时的消息、已记录的启用评估调用次数，以及最近一次成功调用的风格和原生蒙版模式。如果运行时日志布局或相关消息不可用，则会显示未确认的网络名称。调用次数表示命令已成功录制，不代表 GPU 已完成处理或画面效果已通过验证。

将**日志级别**设为默认的**信息**后，可在 `ReShade.log` 中搜索以下内容：

- `snippet loaded`：实际运行时路径及版本；
- `BuildActiveNetwork config=` 和 `Weight heap request`：所选计算图和权重张量数量；
- `DLSSNR: Created feature`：运行时实际选择的预设和网络，包括回退结果；
- `NR diagnostic: enabled`：成功启用的评估调用，以及其网络、风格、蒙版模式和绑定的运动矢量/蒙版输入。

Small FP8 的运行时名称为 `hnet-crazy-cuckoo-small-fp8`，预设为 2，提供的构建版本包含 77 个权重张量（对齐后共 113,907,200 字节）。张量分配量不等于总显存占用。每个功能都会分别记录评估调用，包括后续层和“保护面部”处理；风格或原生蒙版模式变化时也会记录。NR 在辅助进程中运行时，这些日志同样会写入 `ReShade.log`。

Uplift 不会绑定深度或双向畸变输入。原生引导升频尚未验证可用；降低分辨率时会使用 Uplift 自带的升频功能。全局色调和隐藏的原生 Performance 设置尚未确认有效，因此仍保持隐藏。

**标准版 310.9.16 DLL** 不包含 Ada GPU 内核：仅绕过架构检查，仍无法在 RTX 4090 上加载其 FP8 网络。另行提供的 Ada 兼容性原型会使用其他 Ada 内核执行 Small FP8。原生蒙版混合模式默认为 **1**；模式 0 使用不同的蒙版组合方式，画面变化可能不明显。已保存的选择会保留。兼容运行时下完整的蒙版组合行为仍在验证中：供体预处理内核缺少新增的蒙版字段。已在 1080p/D3D12 下演示运行，但尚未验证其效果与原生 Blackwell 是否一致。

另行提供的 Shortfuse **compat-fp16 310.9.16 / CUDA 13.4.3** 构建也受支持。它保留相同的网络权重和 310.9.16 内核接口，并包含适用于 SM75、SM86、SM89 和 SM120 的 GPU 代码。Uplift 的原生网络诊断支持其扩展后的 DLL 布局。该文件已在 RTX 4090 上通过 Direct3D 12 和原生 Vulkan 测试；此处尚未实测其他 GPU 架构。请在**高级 → Runtime path**中直接选择此 DLL，重启游戏后即可照常使用“设置”中的网络和蒙版模式选项。该 DLL 会替换当前选择的运行时，不会与 Uplift 早期提供的 NVIDIA DLL 实验性补丁叠加使用。

在独立测试中，已确认原生蒙版模式 0–3 配合原生棋盘格 ControlMask 会产生不同输出。Uplift 会传递所选模式，但常规路径不会绑定该原生蒙版；现有的 `UPLIFT_MASK` 仍在 NR 处理完成后进行合成。界面默认值仍为模式 1。

**保护面部**（位于“外观”区域）会保留角色的光照和阴影，同时避免 NR 改变角色面部形状。此功能开销更高：每帧会额外运行一次 NR，并需要更多显存（4K 下约 1 GB）。调节方法请见[使用指南](https://github.com/ghostinthecamera/GITC-Uplift/wiki/Guide#keep-faces)。

着色器为可选组件：

- **`Uplift.fx`** 会添加 `Uplift` 技术；可在 ReShade 效果列表中拖动它，选择 NR 相对于其他效果的运行位置。不使用该着色器时，NR 会在所有效果之前运行。LaunchPad 和 Lumenite 的运动矢量需要此着色器：
  - **LaunchPad：** 启用 LaunchPad，并将 Uplift 放在它后面。
  - **Lumenite：** 启用 **LUMENITE: Kernel 2.0**，并将 Uplift 放在它后面。Lumenite 需要 Uplift 1.2.0 或更高版本中的 `Uplift.fx`，且不支持 DX9 游戏。
  - 然后将**运动矢量**设为自动，或选择 LaunchPad / Lumenite。两者同时启用时，自动模式会优先使用 LaunchPad。
- **`UpliftMask.fx`** 是一个示例蒙版，可限制 NR 的处理范围。

## 界面语言

使用 Uplift 窗口右上角、启用/快捷键行上的下拉框，可选择 **English** 或 **简体中文 / Chinese**。简体中文是默认语言。选择会保存在现有的 `ReShade.ini` 中（`[Uplift] Language=0` 表示 English，`1` 表示简体中文）。翻译已编译进插件，不需要语言包或额外文件。切换语言不会重启 NR，也不会改变画面效果。

中文显示使用 ReShade 现有的字体支持。ReShade 使用中文时（包括中文 Windows 上的“系统默认”），通常会自动选择兼容字体。如果字符显示为方框，请在 ReShade 的设置中选择支持中文的**全局字体**；已安装时，微软雅黑（`C:\Windows\Fonts\msyh.ttc`）可显示本界面的文字。在 ReShade 6.8 上已检查英文界面配合该字体显示中文的情况。

Uplift 不会自动更改 ReShade 的界面语言或字体设置。语言下拉框的悬停提示已提供中英文版本。

技术标识符、模型名称、配置键和诊断日志保留其规范写法。中文译文以提供的社区翻译为基础，并已整合到当前插件中。

如需贡献或更新翻译，请参阅[翻译贡献指南](CONTRIBUTING.md)，其中说明了如何查找和填写尚未翻译的英文占位内容。

## 各 API 和位数的支持情况

| | DX12 | DX11 | DX10 | DX9 | Vulkan | OpenGL |
|---|---|---|---|---|---|---|
| **64 位** | ✓ + DLSS | ✓ + DLSS | ✓ | ✓ | ✓ + DLSS | ✓ |
| **32 位** | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

- **✓** NR 会处理最终画面；所有控制项都位于 Uplift 选项卡中。
- **+ DLSS** 对使用 DLSS 的游戏，NR 也可以在游戏帧内、DLSS之后运行，并使用游戏自带的运动矢量。在 DX12 和 Vulkan 下也支持帧生成。Vulkan 下需手动选择 DLSS后；自动模式会保持在后处理（见“进阶用法”）。
- 通过模组添加 DLSS 的 DX11 游戏也可以使用。如果模组在自己的 DirectX 12 设备上运行 DLSS，NR 会保持在后处理，Uplift 选项卡也会说明原因。
- **64 位 Vulkan：** NR 会优先在游戏自己的 Vulkan 设备上运行；如果无法运行，则自动切换到专用 DX12 设备，再不行则切换到辅助进程。**详细信息**会说明当前运行位置和原因。**高级 → Vulkan 后处理 NR**可用于手动选择运行方式。只有游戏自身设备（**原生**）支持在游戏的 DLSS 流程内运行 NR。选择 Direct3D 12 或辅助进程后，NR 会切换到后处理，并禁用 DLSS后和DLSS前。如果原生 NR 仅在后处理阶段失败，DLSS后和DLSS前仍可用。
- DXVK 游戏按 Vulkan 游戏处理；dgVoodoo2 游戏按 32 位 DX11 或 DX12 游戏处理。

**已测试游戏：**《鬼武者：剑之道》（DX12）、《最终幻想 XV》（DX11）、《无人深空》（Vulkan）、《最终幻想 XIII：雷霆归来》（32 位 DX9，以及通过 dgVoodoo2 运行的 DX11）。

## 故障排查

Uplift 选项卡顶部的状态卡会说明问题。常见情况如下：

| 状态卡提示 | 处理方法 |
|---|---|
| “未找到 NR 运行时” | 将 `nvngx_dlssnr.dll` 放入插件旁的 `GITC-Uplift` 文件夹，然后重启游戏。 |
| “移动 nvngx_dlssnr.dll” | 将 `nvngx_dlssnr.dll` 从游戏 `.exe` 所在目录移至插件旁的 `GITC-Uplift` 文件夹，然后重启游戏。 |
| “NR 运行失败”，并显示 NVIDIA 错误代码 | `nvngx_dlssnr.dll` 可能不适用于你的显卡（参见“所需组件”），也可能是显卡驱动版本过旧。 |
| “Uplift 的 64 位辅助进程已停止” | 将同一发行版中的 `gitc-uplift-helper64.exe` 复制到插件旁，然后点击**立即重试**。 |
| “GPU 设备已移除” | 如果状态卡提供按钮，请点击**立即重试**；否则重启游戏。设备停止后，部分显存（4K 下为 1 GB 或更多）会一直占用到游戏退出。如果连续发生两次，请重启游戏并附上 `ReShade.log` 报告问题。 |
| “NR 至少需要 640x360” | 提高游戏分辨率或窗口尺寸。 |
| “NR 已跳过：显存需求 1.2 GB，可用 0.6 GB” | 游戏已占用大部分显存。请降低**显存余量**，或在“高级”中将**显存检查**设为**宽松**或**关闭**。 |
| Vulkan 游戏在启动时因 Uplift 崩溃 | 再次启动游戏；Uplift 会自动关闭对游戏 Vulkan 设备的扩展。如果仍然崩溃，请在“高级”中将**Vulkan 后处理 NR**设为**辅助进程**。 |
| 极低分辨率下 NR 开销很大 | 将**层数**设为 1。分辨率低于约 720p 时，NR 的运算开销不会随画面尺寸明显下降，因此降低**分辨率**的帮助有限。 |
| 在**后处理**阶段使用 **DLSS** 运动矢量，移动镜头时画面闪烁 | 游戏可能以倒置方向保存图像（许多 Unity 游戏如此）。请在 ReShade 的全局预处理器定义中将 `RESHADE_DEPTH_INPUT_IS_UPSIDE_DOWN` 设为 1（与深度效果的设置相同）；Uplift 随后会校正 DLSS 运动矢量的方向。 |
| 启用**保护面部**后，角色出现亮点或发光斑点 | 勾选“高级”中的**显示面部蒙版**并进行调节；参见[使用指南](https://github.com/ghostinthecamera/GITC-Uplift/wiki/Guide#keep-faces)。 |
| “检测到其他 NR 工具正在运行” | 移除其他 DLSS 5 插件（见“其他 DLSS 5 插件”），然后重启游戏。 |
| “Vulkan 交换链无法接收 NR 的结果” | 将 ReShade 更新至 6.8（安装程序中选择**仅更新 ReShade**）。如果提示独占全屏问题，请切换到无边框或窗口模式。 |
| “32 位游戏地址空间不足” | 为游戏应用 4 GB（大地址感知）补丁。 |

仍无法解决？请[提交 Issue](https://github.com/ghostinthecamera/GITC-Uplift/issues)，并附上：

- `ReShade.log`（位于 `ReShade.ini` 旁，通常在游戏目录中）；
- 状态卡内容及**详细信息**中的各行；
- 显卡型号、驱动版本和 ReShade 版本；
- 游戏名称。

## 已知限制

- 如果 NVIDIA NR 在 GPU 上崩溃，游戏也可能崩溃（与任何 GPU 崩溃相同）。请重启游戏，并附上 `ReShade.log` 报告问题。

## 进阶用法

发行版包含 `gitc-uplift.addon64`、`gitc-uplift.addon32`、`gitc-uplift-helper64.exe`、`Uplift.fx` 和 `UpliftMask.fx`。游戏需要哪些文件取决于所用 API 和位数；如需精简安装，不必放入所有文件。

| 游戏类型 | ReShade 插件目录所需文件 |
|---|---|
| 64 位 Direct3D 10、11 或 12、Vulkan、OpenGL | `gitc-uplift.addon64` 和 `GITC-Uplift\nvngx_dlssnr.dll` |
| 64 位 Direct3D 9 | `gitc-uplift.addon64`、`gitc-uplift-helper64.exe` 和 `GITC-Uplift\nvngx_dlssnr.dll` |
| 任意 32 位游戏 | `gitc-uplift.addon32`、`gitc-uplift-helper64.exe` 和（64 位）`GITC-Uplift\nvngx_dlssnr.dll` |

- `nvngx_dlssnr.dll` 也可以直接放在插件旁，或放在你通过**高级 → Runtime path**指定的位置。请勿放在游戏 `.exe` 旁：RTX 50 系列显卡上的 NVIDIA DLSS 会优先从那里加载 DLL，Uplift 无法使用该副本。
- 插件文件和 `gitc-uplift-helper64.exe` 必须来自同一发行版。

### 不同类型游戏所需的 ReShade 安装方式

- **DX10、DX11、DX12：** 常规 ReShade 安装。
- **DX9：** 将 ReShade 安装为 `d3d9.dll`。NR 每帧会通过内存复制画面，1080p 下开销约 3 ms。启用“高级”中的**使用 Direct3D 9Ex**并重启游戏后，开销可降至约 0.4 ms。如果游戏无法启动，请再次启动；Uplift 会自动关闭该选项。
- **Vulkan（含 DXVK）：** 使用 ReShade 6.8 的 Vulkan Layer。运行安装程序，选择游戏可执行文件并选择 **Vulkan**。如果安装程序找到 `ReShade.ini`，请选择**仅更新 ReShade**（卸载会删除 `ReShade.ini`）。通过 DXVK 运行的游戏必须使用 Vulkan Layer，不能使用 `d3d9.dll` 或 `dxgi.dll` 版 ReShade。
- **OpenGL：** 将 ReShade 6.8 安装为与游戏位数匹配的 `opengl32.dll`。
- **通过 dgVoodoo2 运行的旧版 DX8 和 DX9 游戏：** 性能优于纯 DX9。将 dgVoodoo2 的 `MS\x86\D3D9.dll`（或 `D3D8.dll`）放在游戏目录中，在 `dgVoodooCpl.exe` 中将 **Output API** 设为 Direct3D 11 或“Direct3D 12（feature level 12.0）”，再将 32 位 ReShade 安装为 `dxgi.dll`。其他 `d3d9.dll` 包装器（例如 DXVK、游戏修复补丁）会与其冲突。

### 一致的画面处理

所有运行阶段和分辨率都会使用相同的处理顺序：从原始输入测量/选择曝光、准备 NR 输入、运行已配置的处理层、提取 NR 的亮度和颜色变化、按需塑形/稳定变化，最后将变化合成回原始图像。每层都有独立的控制项和运行位置。编码、白色归一化和可用的游戏曝光取决于所选输入源。

当尺寸相同时会跳过缩放。降低分辨率时，NR 前会先执行线性光空间面积平均，再使用所选方式放大变化。测光启用时会采样原始输入；处理尺寸改变会重置空间历史，但不会突然改变曝光适应过程。测光位置、编码、解析后的原色或输入归一化发生变化时，测光会重新初始化。

1.6.0 版本在全分辨率和低分辨率下使用相同的变化场重建方式，SDR 下也包括 Transfer 和 Colour 强度。因此，之前使用旧版全分辨率重建的配置可能会改变画面效果。这一改动优先保证处理方式一致；不同输入图像或处理分辨率仍不会因此产生完全相同的结果。

每个有效运行阶段组的每个处理像素需要 8 字节变化场。原先使用快捷路径的全分辨率处理现在会多一次 GPU 调度，并额外占用约 15.8 MiB（1080p）、28.1 MiB（1440p）或 63.3 MiB（4K）。已使用变化场的路径，其变化场开销不变。预计不会普遍提升 FPS。

在 RTX 4090 上，D3D12 报告的这些变化场已提交资源分配大小分别为 16.875 MiB、30 MiB 和 63.75 MiB。差额来自驱动分配填充；现有预算和中间字节数统计的是上文逻辑图像负载大小。

在 RTX 4090 上进行的针对性 DX12 GPU 检查通过了 90 个编码/变化提取/合成用例，覆盖全分辨率和低分辨率下的 sRGB、场景线性 BT.709、PQ、scRGB 和 scRGB-nl。检查覆盖强度、子区域、Alpha、恒等结果、非有限 NR 输出以及与 CPU 参考结果对比的零蒙版。直接读取变化场与 1:1 Classic 采样逐位一致；合成的最大相对误差为 0.00000525。恒等用例还测试了镜像的 640x360 画布。另外 62 帧 GPU 测光结果与 CPU 调节器一致，覆盖平滑适应、显式跳变和场景切换。这些检查使用受控的 NR 输出；没有运行 NVIDIA NR 网络或挂接游戏的运行阶段。

#### 单层输入复用与后续回归检查

当一个运行阶段组中恰好只有一个 NR 层时，变化提取会从模型纹理 A 读取保留的 FP16 输入。这样可以避免重复执行输入颜色准备和降采样，使用相同的变化方程，且不额外分配图像。多层处理时，纹理 A 会被乒乓覆盖，因此变化提取仍会重新计算原始输入。两个处理后端都使用此规则；桥接和辅助进程 API 沿用 DX12 实现。

后续回归测试使用恒等 NR 替代实现，运行了实际 DX12 `NrPipeline` 和 `Session`：共 15 帧、13 次处理资源重分配，测试了仅改变输出的控制项、原色/归一化变化以及全部三个输入记录器。处理尺寸改变时曝光适应持续运行；实际图像解释方式改变时才重新初始化。一个隔离测试副本恢复了旧的重置耦合，并在第一次尺寸变化时失败，确认该回归测试能检测原始问题。非恒等的一层、两层和三层用例也通过，包括逐层强度、纹理 A 被覆盖后的回退路径，以及单层“保护面部”副本。这些检查在 RTX 4090 和 D3D12 软件适配器上通过；它们不会执行 NVIDIA NR 网络。

另外 60 个硬件 GPU 用例使用带偏移输入/输出区域的渐变和棋盘格，覆盖五种颜色编码、带填充画布，以及 direct/Classic/Edge-aware 合成。复用和重新计算的 FP16 变化场及色度基底逐位一致。输入准备和最终插值也与 CPU 参考计算进行了比较；编码输入的最大绝对误差为 0.00050539，合成的最大相对误差为 0.00001165。

### NR 运行位置与显存

- **64 位游戏**会在游戏进程内运行 NR。首次启用后，约 165–190 MB 会一直由游戏占用到游戏退出，因此再次启用 NR 时无需重新加载。
- **32 位和 DX9 游戏**会在 `gitc-uplift-helper64.exe` 中运行 NR。Uplift 会在 NR 启用时启动此轻量级后台进程；关闭 NR 数秒后，进程会退出并释放其占用的显存。
- **64 位 Vulkan 游戏**会在游戏自己的 Vulkan 设备上运行 NR，包括后处理和 DLSS阶段。首次使用后，NVIDIA 驱动会为游戏保留约 0.5–0.6 GB 显存，直到游戏退出。如果无法通过该方式运行，NR 会切换到游戏进程中的专用 DX12 设备，再切换到 `gitc-uplift-helper64.exe`；部分程序（例如会预留大部分显存的模拟器）需要最后一种方式。后两种方式只支持后处理。
- **Vulkan 设备：** 游戏创建 Vulkan 设备时，Uplift 会为其添加三个共享扩展，使 GPU 能与游戏保持同步；当**Vulkan 后处理 NR**设为原生时，还会添加 NR 在游戏设备上运行所需的四个 NVIDIA 扩展。如果游戏因此出现问题，Uplift 会自动先移除 NVIDIA 扩展，再移除其余扩展（见下文的 `AdjustVulkanDevicesForNgx` 和 `AdjustVulkanDevices`）。NR 仍可运行，但速度会稍慢。
- **多重采样图像（MSAA）：** DX9 和 OpenGL 需要启用 `Uplift` 技术。DX10 和 32 位 DX12 无法在 NR 下使用 MSAA；请在游戏中关闭它。

### DLSS后图像覆盖范围

1.4.2 会在 NGX 创建功能时重写参数块的情况下，保留已提交的 DLSS 渲染尺寸和输出尺寸。此修复解决了《Forspoken》中观察到的 DLSS后 NR 仅覆盖部分画面的问题。输出子区域的起点和动态渲染尺寸仍按原有方式处理。

### 后处理阶段的 DLSS 运动矢量

在 DX12 和 Vulkan 的后处理阶段，如果游戏将 DLSS 运动矢量标记为包含相机抖动，Uplift 会移除这部分抖动。计算使用游戏当前和上一帧的渲染分辨率抖动值，无需新增设置。未标记为抖动的运动矢量仍按原有方式处理。

如果遇到闪烁，请在**高级 → 日志级别**中选择**调试**，复现几秒并附上 `ReShade.log`。首次 DLSS 摘要会报告是否存在抖动；`Present motion` 日志行会显示当前、较旧及缺失的副本、繁忙副本数量和最近一次校正量。DX12 日志还会统计流水线重置提示。

### 不同运行阶段的处理层

**处理层数**设为 2 或更高时，每个 Pass 区域都会显示**运行阶段**，用于选择该层在游戏帧中的运行位置（默认跟随前一层）。DLSS前运行的层会使用游戏渲染分辨率，因此开销更低；例如，第 1 层在 DLSS前运行，第 2 层在后处理运行。此功能适用于原生 DX12、使用 DLSS 的 DX11，以及将**Vulkan 后处理 NR**设为原生的 Vulkan 游戏；其他情况下所有层都会在同一阶段运行。详情请见[使用指南](https://github.com/ghostinthecamera/GITC-Uplift/wiki/Guide#passes-at-different-stages)。

### 跨 DX12 队列的实验性处理层

**高级 → 允许跨队列处理层（DX12，实验性）**可在游戏 DLSS 和后处理使用不同 GPU 队列时，让后续处理层仍在后处理运行，包括帧生成开启时。此项默认关闭；关闭后会恢复现有的回退行为，即改在 DLSS阶段运行。此选项仅适用于 64 位 DX12 游戏。Vulkan 保留原有队列限制。

启用此项和**帧生成期间处理后处理**时，二者都会分别显示确认窗口：

- **跨队列处理层**可能因处理层争用 GPU 而降低 FPS 或增加延迟，也可能造成画面差异或不稳定。
- **帧生成期间处理后处理**可能带来显著开销：每个后处理层也会处理生成帧；在 3 倍/4 倍帧生成下，每个游戏渲染帧可能运行三次或四次，从而抵消帧生成的大部分性能收益。

帧生成开启时，必须同时启用这两个选项，才能保留跨队列的 DLSS后/后处理分层。请在各自警告中选择**仍要启用**；选择**保持关闭**、关闭窗口或按 Escape 都会保持禁用。跨队列选项不会增加图像副本、运行时或 CPU 等待；两个阶段使用游戏现有的图像交接机制，兼容性和开销取决于游戏及运行时。

### 各层可独立选择网络

使用 NR 310.9.16 时，第 2–10 层的设置区域会在**运行阶段**旁显示**网络预设**：

- **与第 1 层相同**会沿用“设置”中的网络（默认值，也适用于现有配置）。
- **A：Legacy**或**B：Small FP8**可为该层单独选择网络。

例如，可在“设置”中选择 Legacy 并将阶段设为 DLSS前，再将第 2 层设为 Small FP8 和 DLSS后。**与第 1 层外观相同**只共享外观设置；网络和运行位置仍可独立选择。

切换网络会重新创建功能池并重置其历史记录。“保护面部”使用所在阶段组中第 1 层的网络。**详细信息**会报告每个已创建且被请求的处理层经运行时确认的网络和评估调用记录数。NR 310.8 会禁用所有网络选择器并显示 Legacy，同时保留已保存的选项供较新运行时使用。混合网络链采用保守的显存估算；使用 Small FP8 不保证显存预留更少。

| `FaceMaskStrength` | `2` | **蒙版强度**（高级），范围 0.5–4：如果面部蒙版内部有空洞，提高此值；如果蒙版范围过大，则降低此值。 |
| `FaceMaskSoftness` | `0.5` | **蒙版柔化（画面高度百分比）**（高级），范围 0.1–2：如果蒙版斑驳或闪烁，提高此值；如果蒙版蔓延到面部以外，则降低此值。 |
| `FaceEdgeFalloff` | `0.15` | **边缘衰减（画面高度百分比）**（高级），范围 0.05–1：如果光照溢出到角色轮廓外，降低此值；如果轮廓出现暗边，则提高此值。 |
| `FaceLightingDensity` | `0.3` | **光照密度**（高级），范围 0.05–1：如果高光或明亮边缘使角色出现亮点，提高此值；如果面部边缘附近的光照消失，则降低此值。 |
| `FaceSpeckSize` | `2` | **去除亮点（像素）**（高级），范围 0–3：不超过此尺寸的亮点（反光、闪光）会保留 NR 的常规结果。尺寸越大，越可能停止保护微小面部细节（例如远处的人眼）。`0` 表示关闭。 |
| `FaceFillSkin` | `1` | **按颜色填充皮肤区域**（高级）：设为 `1` 后，会将蒙版扩展到附近颜色相同的皮肤区域（例如阴影中的皮肤）。如果类似肤色的衣物或头发变成洋红色，请设为 `0`。 |
| `FaceFillRadius` | `3` | **填充半径（画面高度百分比）**（高级），范围 0.5–10：控制填充从已标记皮肤向外延伸的距离。大块皮肤仍未覆盖时可提高此值；填充蔓延到附近表面时可降低此值。 |
| `FaceFillTolerance` | `0.04` | **颜色容差**（高级），范围 0.005–0.2：阴影中的皮肤仍未覆盖时可提高此值；衣物或头发变成洋红色时可降低此值。 |

### 状态卡的其他提示

- **“与旁边的 Uplift 插件版本不一致”：** 插件和 `gitc-uplift-helper64.exe` 来自不同发行版。请从同一发行版重新复制两者。
- **“NR 可用显存不足”**或**“已暂停：游戏需要更多显存”：** 降低**分辨率**或**处理层数**，关闭其他 GPU 程序，或在“高级”中将**显存检查**设为 Relaxed 或 Off。
- **“保护面部已暂停”：** 显存不足以支持额外的 NR 运行。NR 会在不保护面部的情况下继续运行；显存充足后会自动恢复。请降低**分辨率**或**处理层数**以腾出显存。
- **“保护面部已停止”：** 额外的 NR 运行失败，但 NR 会在不保护面部的情况下继续运行。取消勾选后重新勾选**保护面部**即可重试。
- **“DLSS后运行 NR 已关闭”**（GPU 崩溃后）：NR 会保持在后处理。点击 Clear latch 后，从下次启动起会重新尝试 DLSS后运行。
- Uplift 在 `ReShade.log` 中的日志行以 `[Uplift]` 开头；如需更多信息，请在“高级”中将**日志级别**设为 Debug。64 位游戏日志末尾出现 `Add-on "GITC Uplift" was not unregistered!` 属于正常情况。

## 从源码构建

需要准备：

- **Visual Studio 2026** 或 **2022**（17.14），任意版本，并安装 **使用 C++ 的桌面开发**工作负载（其中包含 CMake、Ninja 和 Windows SDK；Windows SDK 提供用于编译 Direct3D 着色器的 `dxc.exe`）；
- **Vulkan SDK**（设置 `VULKAN_SDK` 环境变量），用于提供头文件和编译 SPIR-V 着色器所需的 `dxc.exe`；
- **Git**，以及首次构建时所需的网络连接。

然后在命令提示符中执行以下命令（在 PowerShell 中输入 `.\build.cmd` 和 `.\tools\fetch_deps.cmd`）：

```bat
git clone https://github.com/ghostinthecamera/GITC-Uplift.git
cd GITC-Uplift
tools\fetch_deps.cmd
build.cmd release
build.cmd release-x86
```

- `tools\fetch_deps.cmd` 会将构建所需的头文件下载到 `third_party\_deps`（NVIDIA NGX SDK 头文件，不含 NVIDIA 二进制文件；ReShade 6.0.0 插件头文件和 Dear ImGui；MinHook）。
- `build.cmd release` 会生成 `build\release\gitc-uplift.addon64` 和 `build\release\gitc-uplift-helper64.exe`。
- `build.cmd release-x86` 会生成 `build\release-x86\gitc-uplift.addon32`。
- 插件和辅助进程会检查彼此的构建 ID，因此必须始终使用同一次构建生成的文件。
